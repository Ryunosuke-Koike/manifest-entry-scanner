# 開発ログ

作業の経緯と学びを残し、同じ失敗や手戻りを防ぐための記録です。新しい記録を下へ追記します。秘密情報、APIキー、パスワードは記載しません。

## 記録項目

- 日時
- Goal・タスク・Issue・PR
- 作業者または担当役
- 作業開始時の状態
- 実施内容
- テスト・確認結果
- 発生した問題、失敗、手戻り
- 原因
- 対応内容
- 次回への改善
- 更新した計画・タスク・手順

## 2026-08-21: 安全な案件初期化機能の実装

- Goal・タスク・Issue・PR: T-008、GitHub Issue #5
- 作業者または担当役: 統括・実装エージェント
- 作業開始時の状態: PR #2の作業ブランチ上。生成済みディレクトリがローカルで削除状態だったため、コミット済み内容から復元して既存成果物を保全
- 実施内容: `reset-project-state` スキル、初期状態テンプレート、安全検査付きPowerShellスクリプト、実動作テスト、起動語、リポジトリ分離ルールを追加。判断ログをスターター共通と現在案件に分離
- テスト・確認結果: 外部一時Gitリポジトリを使用し、既定ブランチ、upstream同期ずれ、未コミット変更、コピー不一致、確認文字列不一致で変更前に停止することを確認。正常系では案件固有状態だけが初期化され、過去ログと共通判断が維持され、生成物が復旧用領域へ移動することを確認。PowerShell構文、スキルメタ情報、`git diff --check` に合格
- 発生した問題、失敗、手戻り: 最初のパッチで同じスキルファイルの削除と追加を同時指定し拒否された。雛形の想定行と実際の内容が異なる更新パッチ、複数ファイルのうち1つだけ文脈が一致しないパッチも拒否された。標準スキル検証器は `PyYAML` がないため実行できなかった
- 原因: 過去ログにある編集ツール制約を最初の操作で再確認できていなかった。生成された雛形を読む前に一般形を仮定した。大きな複合パッチへ文脈の異なるファイルを含めた。検証器の依存関係が環境にない
- 対応内容: 既存ファイルを先に読み、更新と新規追加を分割し、関連単位ごとの小さいパッチへ変更。外部ライブラリを無断追加せず、メタ情報の手動検証、PowerShell構文解析、実動作テストで補完
- 次回への改善: 生成ツールが作ったファイルは必ず内容を読んでから編集する。複数ファイルパッチは文脈一致を先に確認し、失敗時に同じ形式を繰り返さない。スキル標準検証器の依存関係はスターター環境の整備課題として別途扱う
- 更新した計画・タスク・手順: `AGENTS.md`、`README.md`、`docs/`、`decisions/DECISION_LOG.md`、`tasks/TASKS.md`、`reviews/`、開発開始・案件初期化スキル、初期状態テンプレート、テスト
