# 慎重派レビュー

## 対象

実装前の要件、Goal、技術構成、スプレッドシート構造、タスク、実装起動ルール

## 結論

重大な未解決事項はない。実装前に確認すべき中程度のリスクがGoal 1とブロッカーへ明記されており、実装用プロジェクトとして引き渡し可能。

## 指摘

### 中程度

1. Apps Script HTML Serviceはiframe内で動くため、iPhone/SafariとAndroid/Chromeのカメラ利用を保証できない
   - 対応: Goal 1の最初に両実機で撮影だけを検証する
2. Apps Scriptの実行方法によって、ログイン中メールアドレスが空になる可能性がある
   - 対応: 同一Workspaceドメインで実測し、取得できない場合は実装を広げず判断を待つ
3. Tesseract.jsの初回Worker・モデル読み込みが3秒目標へ影響する
   - 対応: 初回準備時間と2枚目以降を分離し、バージョンとHTTPS配信元を固定する
4. 画像非送信は設計だけでなく通信記録で確認する必要がある
   - 対応: ネットワーク記録で画像、Blob、Data URLが送られないことを確認する
5. 同時利用時は重複確認と追加の間に競合が起きる
   - 対応: Script Lock内で重複確認と追加を一続きで行う

### 軽微

- 会社ルール上の保存期間は未確定
- 70枚では99%以上を統計的に十分証明できないため、初期検証後にサンプル追加を判断する
- 音・振動は端末差があるため、画面表示を必須の通知手段にする

## 良い点

- 撮影画像をGit、Apps Script、スプレッドシートへ保存しない境界が明確
- `.clasp.json`、見本画像、OCRモデルをGit管理対象外にしている
- スプレッドシートIDをScript Propertiesで管理する方針
- 行削除ではなく取消状態を残す
- 目標未達時にクラウドOCRへ自動移行しない
