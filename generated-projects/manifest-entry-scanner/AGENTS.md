# AGENTS.md

## 0. 実装の起動

利用者が次のいずれかを独立した指示として入力した場合、`.codex/skills/start-implementation/SKILL.md` を読み、実装フローを開始する。

- `実装スタート`
- `実装開始`
- `アプリ実装スタート`
- `START IMPLEMENTATION`
- `/start-implementation`

単に「実装」という語を含む質問、引用、説明依頼では開始しない。

## 1. プロジェクト固定

1. この `AGENTS.md` があるディレクトリをプロジェクトルートとする。
2. コピー後の初回実装開始時に、現在のディレクトリに `PROJECT_ROOT.md` と `AGENTS.md` があることを検証する。端末固有の絶対パスは追跡ファイルへ記録しない。
3. ソース、テスト、設定、計画、ログ、レビューなどの成果物は、すべてプロジェクトルート内へ保存する。
4. 親ディレクトリや別プロジェクトへ成果物を作成しない。OSの一時領域やツールキャッシュは例外だが、最終成果物として依存しない。
5. 人が明示的に別プロジェクトへの切り替えを指示しない限り、完了までこのプロジェクトルートを使う。

## 2. 作業前の確認

作業前に次を読む。

- `PROJECT_ROOT.md`
- `PROJECT_BRIEF.md`
- `docs/REQUIREMENTS.md`
- `plans/MASTER_PLAN.md`
- `tasks/TASKS.md`
- `decisions/DECISION_LOG.md`
- `docs/GIT_WORKFLOW.md`
- `logs/DEVELOPMENT_LOG.md`

不明点が成果物へ影響する場合は、実装前に1問ずつ確認する。各質問には推奨回答と理由を付ける。

## 3. Gitとレビュー

1. 実装開始時にGit管理を開始する。
2. リモートは人が作成したURLを確認して接続し、自動作成や推測をしない。
3. 最初の実装前に、生成済みの計画・設定一式を日本語で初回コミットし、リモートへプッシュする。
4. 以後の変更や新機能追加前にも、直前の正常な状態をコミット・プッシュする。
5. 影響の大きい作業は、Issue、対応ブランチ、PRを使用する。
6. PRは人がレビューし、人がマージする。明示的に依頼されない限り、Codexはマージや自動マージ設定を行わない。
7. コードコメント、コミット、Issue、PR、レビュー返信、開発ログは、固有名詞やコードを除いて日本語で記述する。

## 4. 開発方法

1. 一度に大きな完成形を作らず、Goalとタスクの単位で実装する。
2. 各Goalに確認可能な完了条件を設ける。
3. 実装後は自動テストと手動確認を行う。
4. 慎重派と実用派の2種類のレビューを別々に行い、統括役が採用・保留・却下を判断する。
5. 作業内容、テスト、失敗、原因、改善策を `logs/DEVELOPMENT_LOG.md` に記録する。
6. 統括役はログを確認し、同じ失敗を防ぐために計画、タスク、手順を更新する。
7. 秘密情報をソースコードやログへ直接記載しない。

## 5. 完了条件

- 実装が存在する
- 動作確認方法と結果が記録されている
- 重大なレビュー指摘が解消されている
- タスクと開発ログが更新されている
- 影響の大きい作業ではPRが作成され、人のレビュー待ちになっている
