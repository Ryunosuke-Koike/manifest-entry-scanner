# Start Implementation

## 起動語

- `実装スタート`
- `実装開始`
- `アプリ実装スタート`
- `START IMPLEMENTATION`
- `/start-implementation`

起動語が独立した開始指示である場合だけ実行する。

## 実行手順

1. 現在のディレクトリに `AGENTS.md`、`PROJECT_ROOT.md`、`PROJECT_BRIEF.md` があることを確認する。なければ実装せず、正しいプロジェクトディレクトリを開くよう案内する。
2. `PROJECT_ROOT.md` と `AGENTS.md` がある現在のディレクトリを、この実装セッションのプロジェクトルートとして確定する。端末固有の絶対パスは追跡ファイルへ記録せず、以後の成果物をこのルート内に限定する。
3. `AGENTS.md` に列挙された必須文書と `logs/DEVELOPMENT_LOG.md` を読む。
4. 要件、技術構成、Goal、最初のタスクに実装を妨げる不明点があれば、質問を1問ずつ行う。各質問に推奨回答と理由を付ける。
5. Git未初期化なら初期化する。
6. 人が作成したリモートURLを質問し、提示されたURLを復唱して確認を得てから `origin` に接続する。リモートを自動作成・推測しない。
7. 接続を検証し、生成済みプロジェクト一式を日本語の初回コミットで保存してプッシュする。プッシュできない場合は実装を開始せず、原因と必要な対応を伝える。
8. `tasks/TASKS.md` の先頭の実装可能タスクから、小さな単位で実装する。
9. 影響の大きい作業では、実装前にIssueを作成して対応ブランチへ切り替える。
10. 実装、テスト、慎重派レビュー、実用派レビュー、統括判断、修正を行う。
11. 影響の大きい作業はPRを作成し、人のレビュー待ちで止める。マージしない。
12. すべての作業結果と改善策を開発ログへ記録する。

## 停止条件

- 正しいプロジェクトルートを確認できない
- 重要な要件が未確定
- リモートURLが未提示または未確認
- リモート接続または初回プッシュに失敗
- 人の判断が必要な破壊的変更や大きな方針変更がある

停止時は、判明した内容、実施済み作業、次に人が行うことを日本語で示す。
