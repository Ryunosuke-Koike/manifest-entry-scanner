# 合言葉で開発フローを起動する方法

## 推奨する起動語

Codexのチャットで、次の一言を入力します。

```text
開発スタート
```

作りたいものが決まっている場合は、続けて書けます。

```text
開発スタート 社内で使用する在庫管理アプリ
```

コマンド風に使いたい場合は、次でも起動できます。

```text
/start-app-dev
```

## 「開発スタート」で行われること

1. 開発ルールと現在のプロジェクト情報を確認します。
2. 推奨回答と理由を付けたGrill-me方式で、質問を1問ずつ行います。
3. 回答に応じた関連質問を続け、重要な不明点を解消します。
4. 要件要約を提示し、人の確認を得ます。
5. 「動く最小版」「試用版」「安定運用版」の段階的なゴールを提案します。
6. 使用する技術やサービスを、用途・理由・費用・代替案付きで説明します。
7. `generated-projects/<project-slug>/` に、別の場所へコピーできる実装用プロジェクトを生成します。

この段階ではアプリ本体を実装しません。

## コピー後の実装起動語

生成されたディレクトリを別の場所へコピーし、Codexでコピー先を開いて次のいずれかを入力します。

```text
実装スタート
実装開始
アプリ実装スタート
/start-implementation
```

実装開始後は、現在のコピー先をプロジェクトルートに固定し、Git接続、実装、テスト、二重レビュー、PR作成まで進めます。PRのマージは人が行います。

## 次の案件へ進むための初期化語

前案件のコピー、コミット・プッシュ、PRレビューが完了した後、スターターで次のいずれかを独立した指示として入力します。

```text
初期状態に戻す
案件初期化
次の開発準備
/reset-project-state
```

初期化は事前検査と人の確認を二段階で行います。生成物は直接削除せず復旧用に退避し、スターター機能、開発ログ、運用ルール、Git履歴を維持します。初期化PRを人がマージした後、次の「開発スタート」を使用できます。

## 注意点

この仕組みは、OSのキーボードショートカットのように文字入力を機械的に置き換えるものではありません。
`AGENTS.md` とスキルの起動条件をCodexが読み、独立した開始指示として入力された合言葉に反応する仕組みです。起動語について質問したり引用したりしただけの場合は開始しません。

確実に起動させたい場合は、開発開始には `/start-app-dev`、案件初期化には `/reset-project-state` を使用してください。
