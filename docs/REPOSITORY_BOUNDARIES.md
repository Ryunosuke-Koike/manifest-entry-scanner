# リポジトリの役割分離

## 目的

再利用する開発スターターと、生成後に実装する各アプリの履歴・Issue・PRを混在させない。

## スターター用リポジトリ

このディレクトリを管理する。次だけを扱う。

- 開発開始、詳細要件確認、プロジェクト生成、案件初期化の機能
- 共通のエージェント、スキル、テンプレート、テスト
- 開発手順と継続改善ログ
- 生成・初期化作業に関するIssueとPR

人がスターター専用リポジトリを作成し、URLを確認した後に `origin` として接続する。Codexはリポジトリを自動作成しない。

## アプリ用リポジトリ

`generated-projects/<project-slug>/` を別の場所へコピーしたディレクトリを管理する。

- アプリ固有の要件、判断、計画、ソース、テスト
- 実装、修正、リリースに関するIssueとPR
- アプリ固有の秘密情報を除く設定

コピー先で「実装スタート」を入力した後、人がアプリ専用リポジトリのURLを提示し、確認後に接続する。

## 禁止する混在

- スターターとアプリで同じリモートURLを継続利用しない
- アプリの実装コードをスターター直下へ追加しない
- スターターの共通スキルを、必要な検討なしにアプリ固有仕様へ変更しない
- コピー先の `.git` ディレクトリを生成元へ戻さない

## 次の案件へ進む条件

1. アプリ用コピーが独立したGitリポジトリへ保存されている
2. アプリ用リモートとスターター用リモートのURLが異なる
3. 完了案件のPRが人のレビューを経てマージされている
4. スターターの初期化PRが人のレビューを経てマージされている
5. スターターの既定ブランチが最新で、作業ツリーがクリーンである
