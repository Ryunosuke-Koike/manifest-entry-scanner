# Start App Development

## 目的

短い合言葉から詳細な要件確認を開始し、回答を反映した自己完結型の実装用プロジェクトを生成する。このスキルではアプリ本体を実装しない。

## 明示的な起動語

次のいずれかが、利用者から開発準備を始める独立した指示として入力されたら、このスキルを優先して実行する。

- `開発スタート`
- `アプリ開発スタート`
- `Codex開発スタート`
- `START APP DEV`
- `/start-app-dev`

起動語の後ろに文章がある場合、その文章は今回の開発テーマまたは追加指示として扱う。
起動語を引用した質問、仕様確認、説明依頼では起動しない。

例:

- `開発スタート 在庫管理アプリを作りたい`
- `/start-app-dev 社内だけで使う見積アプリ`

## 起動後の処理

1. リポジトリ直下の `AGENTS.md` を読む。
2. `PROJECT_BRIEF.md` を読む。
3. `.codex/skills/app-dev-orchestrator/SKILL.md` を読む。
4. `docs/GENERATED_PROJECT_SPEC.md` と `logs/DEVELOPMENT_LOG.md` を読み、生成仕様と過去の改善策を確認する。
5. [詳細要件インタビュー](references/requirements-interview.md) を最初から最後まで読み、質問を1問ずつ行う。各質問に推奨回答と理由を付け、回答に応じて分岐を掘り下げる。
6. 重要な不明点が解消したら要件要約を提示し、利用者の明示的な確認を得る。
7. 次の3段階を基本としてゴール案を提示する。
   - Goal 1: 動く最小版
   - Goal 2: 実際の利用者が試せる版
   - Goal 3: 安定運用できる版
8. 技術や外部サービスを提案するときは、用途、採用理由、費用、代替案、注意点を説明し、利用者の選択を得る。
9. 計画、タスク、判断事項を整理する。
10. 利用者にプロジェクト名と出力先 `generated-projects/<project-slug>/` を示し、生成の確認を得る。
11. `scripts/create-project-scaffold.ps1` で共通雛形を `generated-projects/<project-slug>/` に生成し、`docs/GENERATED_PROJECT_SPEC.md` に従って確定内容を反映する。同名ディレクトリは無断で上書きしない。
12. 採用技術に合わせたソース、テスト、設定のファイルツリーを生成する。ただし、この段階ではアプリ機能を実装しない。
13. 必須ファイル、内部参照、親スターターへの依存、秘密情報、実装起動スキルを検証する。
14. 利用者へ生成ディレクトリ、コピー方法、コピー先で使う実装起動語を案内して終了する。

## インタビューの原則

- 一度に1問だけ質問する。
- 各質問に推奨回答と推奨理由を付ける。
- 専門用語だけで質問しない。
- 選択肢を示せる場合は、初心者が選びやすい候補を示す。
- 回答によって生じた関連論点を解消してから次へ進む。
- コードや文書から確認できる内容は自分で調べ、同じことを質問しない。
- 重要な不明点を仮定で埋める場合は、影響を説明して利用者の同意を得る。

## 完了時の出力

最低限、次を提示する。

- 確定した開発目的と要件
- 段階的ゴールと採用技術
- 生成した実装用プロジェクトの場所
- 生成した主要ファイルツリー
- 検証結果と残っている保留事項
- 別の場所へコピーする方法
- コピー後に使う実装起動語
